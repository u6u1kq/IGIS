# 2026-10-11 V0.80 隔离工作流回合（补记）

本文为 2026-10-11 补记。V0.80 的实际开发早于本日志，内容依据当时的 TASK 文档与当前代码核对。

新包 `packages/workflow-env`：给策略一个隔离的工作流回合环境。它只被 CLI 检查脚本引用，生产聊天与桌面接口不接入（`workflow-env-check` 有断言防止接入）。

## 模块名

`packages/workflow-env/src/run.ts`，`types.ts`；`apps/cli/src/workflow-env-check.ts`。

## 变更内容

- **WorkflowTask 契约**：taskId/goal/初始图层/允许操作（1–8 个）/完成条件（maxSteps ≤ 8、minSucceededOperations ≤ 8、可选要求某类操作至少成功一次）。
- **createWorkflowRun**：动作先经安全操作名与参数白名单、`boundaryViolation`（文件/GDAL/几何拒绝）、任务允许集、`validateToolArguments`、可选 `blockKnowledgeWrites`、可选 `layerScope`（图层标识与名称必须落在范围内，成功新建的层自动补进范围），再交给现有 `createSpatialAwareAdapter(entry: "chat")` 进入 `executeGisOperation`。来源记 local-user，不冒充 cloud-ai。
- **判定**：`evaluateWorkflow` 只看任务契约与计数；拒绝、执行失败、步数耗尽都不能成功。
- **轨迹**：TrajectoryStep 只存本地运行（destination: "local-run"），不送模型，不进训练。
- `deterministicPolicy` 按给定顺序返回动作，没有模型客户端。

## 验证

`workflow-env-check` 通过：任务归一化、边界拒绝、范围检查、判定计数、轨迹隔离、生产文件未接入。

## 未解决问题

- 策略是进程内函数；隔离不等于进程、网络或文件系统沙箱。
