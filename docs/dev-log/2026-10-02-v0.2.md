# 2026-10-02 V0.2 数据流契约与模型调用

本轮在 V0.1 契约上增加读路径路由、OpenAI 兼容的模型调用、来源账本骨架和许可证门禁。没有 wasm 二进制，没有 DuckDB，没有嵌入库，没有 qgis-wasm，没有训练。未创建 git 提交。`tsc -p tsconfig.json --noEmit` 退出码为 0。

明确推迟：

- GDAL-WASM 二进制和读取实现 → v0.3-1
- DuckDB 实现 → v0.3-1
- SurtGIS 内核算法 → 后续阶段
- RAG 嵌入与索引 → 后续阶段
- OSM 算子验证 → 后续版本
- LoRA / QLoRA 与样本导出 → v1.x+

## gis-io

- 模块名：`@igis/gis-io`
- 变更内容：新增上层读路径包。定义 GDAL-WASM 读端口和 ArcPy 回退端口，以及只依赖注入端口的路由器。OpenFileGDB 标明为只读，且与 ArcGIS Pro 并非 100% 等价。路由器不派生进程，不导入 arcpy，也不导入 gdal。
- 接口契约变更：新增 `GdalWasmReadPort`、`ArcPyReadPort`、`GisReadRequest`、`GisReadResult`、`routeGisRead`、`GisIoReadError`、`GisIoRoutingError`、`OPENFILEGDB_READ_NOTE`。先调用 GDAL-WASM；失败后把同一份请求交给 ArcPy。成功结果只保留内存引用和图层名。
- 未解决问题：两个端口都还没有真实实现。ArcPy 将来若要落地，只能作为独立进程，本阶段没有设计启动方式。没有官方标准的 GDAL-WASM 预编译包。

## shared-types

- 模块名：`@igis/shared-types`
- 变更内容：补上数据面引用和控制面信封，以及几何字节字段的运行时检查。外部 LLM 配置可以指向提供方。OSM 仍不连接真实数据。GPL 策略写明独立进程不拦截。
- 接口契约变更：新增 `DataPlaneRef`、`ControlPlaneEnvelope`、`LlmProviderId`、`assertNoGeometryByteFields`、`findForbiddenPayloadKey`、`looksLikeGeometryText`。`ExternalLlmConfig` 增加 `providerId`。`OSM_POLICY.realOsmConnected` 为 false。`GPL_POLICY.externalProcessGplIntercepted` 为 false。
- 未解决问题：控制面允许图层摘要里的范围四元组留在进程内。该字段不会进入来源账本，也不应发给模型。字符串里的十六进制 WKB 没有单独识别。

## memory-bus

## llm-dispatch

- 模块名：`@igis/llm-dispatch`
- 变更内容：用全局 `fetch` 或注入的 `fetch` 调用 deepseek、千问、grok 和可选本地模型。请求是 OpenAI 兼容的 chat/completions 工具调用。密钥来自参数或环境变量名 `DEEPSEEK_API_KEY`、`QWEN_API_KEY`、`GROK_API_KEY`、`LOCAL_LLM_API_KEY`，不写入配置对象。几何载荷在发请求前被拒绝。本地模型可以不带密钥，但必须提供 `baseUrl`。
- 接口契约变更：`LlmDispatch` 增加 `providerId`。新增 `invokeLlmForToolRequest`、`createExternalLlmDispatch`、`resolveLlmConnection`、`LLM_PROVIDER_PROFILES`、`assertLlmPayload`、`LlmInvokeError`、`runLlmDispatchSelfCheck`。
- 未解决问题：占位基址没有在线探测，校验时也不访问网络。模型名仍由调用方传入，锁文件里的 `model` 为 null。若服务端只返回普通文本、不返回工具调用，当前实现会拒绝，不会从正文里猜测。自检函数不会在导入时自动执行。

## provenance

- 模块名：`@igis/provenance`
- 变更内容：实现内存账本。用 Node 内置 `node:crypto` 计算 SHA-256。记录只保留源内容哈希、只读标记、导出路径、图层名和记录时间。嵌套对象里的几何键会被拒绝，并且不会写入保存结果。`persistJson` 为 true 时，JSON 写到 `var/provenance`（默认已被 gitignore）。禁止字段名单与 `config/audit.json` 一致，没有改动。
- 接口契约变更：新增 `InMemoryProvenanceLedger`、`buildProvenanceRecord`、`prepareProvenanceRecord`、`hashSourceContent`、`assertProvenancePayload`、`ProvenanceLedgerError`、`runProvenanceSelfCheck`。`ProvenanceRecord` 与 `ProvenanceLedger` 的字段保持原契约。
- 未解决问题：`recordId` 仍在类型里，但 `audit.json` 的 `recorded` 列表没有它，本轮不改这两份名单。十六进制 WKB 若放在非禁止键的字符串里，键扫描发现不了。图层名字符串若本身是 WKT，会被拒绝。自检不写盘，导入时也不会自动跑。

## finetune

- 模块名：`@igis/finetune`
- 变更内容：保持占位。增加隐私审查函数签名，表示要检查适配器不能被反推出坐标。没有函数体，不训练，不导出 JSONL / Parquet。注释写明样本永远不包含坐标，也永远不嵌入 OSM 几何。`models.lock.json` 里的微调开关仍为 false / reserved。
- 接口契约变更：`FinetuneReservation` 增加 `samplesContainCoordinates`、`samplesEmbedOsmGeometries`、`privacyReview`。新增类型 `ReviewAdapterCoordinateLeak`。`privacyReview` 常量为 null。
- 未解决问题：审查逻辑、样本导出和 LoRA / QLoRA 都留到 v1.x+。

## license-check
