# 2026-10-05 V0.72 对话到 GIS 工具链检查

上一轮 V0.72 因模型用量上限中断，磁盘上没有半成品。本文件记录检查时的链路，以及随后修了什么。

## 检查对象

用户在对话里说出中文 GIS 指令之后，经过：系统提示 → 每轮上下文 → 工具登记表 → 参数整理 → 图层匹配 → 适配器 → 图层库/内核 → 返回模型 → 页面展示。坐标不得进入模型、RAG、账本、空间审计或日志。

## 发现

### 系统提示

`runLlmToolCallLoop` 原来只有两句：只能调用给定工具、不要输出几何。没有说明：

- 用图层名还是 `lyr-` 标识；
- 中文单位怎么写；
- 多步时如何接上一步的结果图层；
- 名字有歧义时不要猜；
- 样式、显隐、顺序、缩放、导出其实已经有图层库接口，但模型看不到。

### 每轮图层上下文

`runAssistantTurn` 只把问题和 RAG 片段放进 `instruction`。`visibleDispatchContext` 的 `metadata` / `kgHits` 在对话路径里是空数组。模型看不到当前已载入地图的图层。local-mock 只能从正文里用 `图层 lyr-abc` 这种写法抠标识。

### 工具登记表

登记表里同时有 `list-layers`、`io.read`、`map.buffer`、`gdl.run`。对话实际只下发查询、空间、GDL 三组，不含 `io.read`。`vector.buffer` 等旧名不认识。样式、显隐、顺序、缩放到图层、GeoJSON 导出在 HTTP 和图层库里已经有，但不是工具。缓冲结果不能由模型命名。

### 图层名和单位

适配器把 `layerId` 直接交给 `catalog.get`。用户说「道路」就会失败。单位在 `normalizeUnit` 里其实认得「米」，但进适配器之前如果模型把距离写成 `"200"` 字符串，校验会直接抛错并中断整轮对话。

### 错误回传

空间适配器失败时已经返回 `{ok:false,message}`。校验失败（未知工具、类型不对）和只读查询抛错会变成 `LlmInvokeError`，整段对话 500，模型没有机会改参数。同一错误可以无限重试，直到 `maxRounds`。

### 多步结果

`maxRounds` 默认 4，缓冲再相交其实够用。真正的问题是 local-mock：`done === 0` 时只调一次工具，之后直接结束。上一步的 `layerName` 不会进入下一步。

### 把工具写在正文里的提供方

循环只认 `tool_calls`。有的接口把 JSON 写在 `content` 里，会被当成最终回复，工具不会执行。

### 应用里有、模型调不到的能力

图层库已有：`updateStyle`（含显隐）、`setOrder`、`exportTo`。页面载入时用 `fitBounds` 缩放到图层。对话工具没有对应项。报告页签、知识库管理、模型齿轮不是 GIS 工具，也不应假装去调。

## 修复对照

| 问题 | 处理 |
| --- | --- |
| 系统提示过短 | `GIS_SYSTEM_PROMPT` 中文规则 |
| 每轮没有图层 | `mapLayers` 摘要，无坐标、无范围、无路径 |
| 旧名和新名不一致 | `canonicalToolName` 别名；登记表补上 list/load/style/visibility/order/zoom/export |
| 图层名对不上 | `resolveLayerRef`；多个候选返回 `ambiguous-layer` |
| 参数类型死板 | `normalizeToolArguments`：别名、数字字符串、中文单位 |
| 错误中断对话 | 校验/适配器失败写成工具结果送回模型；相同失败两次停止 |
| 正文里的工具 | `parseTextToolCalls` |
| 中文多步 | `planGisInstruction`；local-mock 按步骤调用 |
| 轨迹看不见 | 对话消息保存 traces 和结果图层名 |
