## 变更内容

- 每个对话都可以删除。若删的是唯一一个，清掉它的消息并留下一个新的空对话（新编号即可）。删除按钮保持可用，接口不返回“至少保留一个”的错误。
- 发送后立刻画出用户气泡；请求失败也留着。助手一侧用 SSE：先是默认折叠的思考（提供方若有 reasoning 放进去，否则只给短状态，不编造推理），再按发生顺序列出工具步骤（线上名如 `run_buffer`，不是 `map.buffer`），最后是普通正文。`local-mock` 在正文前发出思考状态和工具步骤。流里不放坐标和密钥。
- 齿轮增加界面语言：简体中文和 English，默认中文。只翻译界面，不翻译已保存的对话。语言与其他界面设置一样随配置保存。
- 后端归一化（紧挨 PendingPlan，不靠加长系统提示）从口语里抽出意图和图层名，包括 `area-a_area-b分离` 这种粘在动词上的名字，以及用「和」连起来的名字。槽位齐了就执行该计划，不再交给模型重解释。缺槽位时只问一句，并记下 PendingPlan；下一句只填槽，不另起分析。成功的工具序列之后不再做第二轮描述、统计或澄清。同一轮里相同的工具加参数只跑一次。
- 「现在先分析图层」且已选中图层：一次 `describe_gdl` 加一次 `summarize_layer`，然后停止。
- 「area-a_area-b分离」：一次 `run_clip`（area-a 被 area-b 裁），然后停止。不裁两次，也不再分析。
- 「对当前图层做 200 米缓冲，再和另一图层相交」之后的「area-a和area-b」：`run_buffer`（area-a，200 米）再 `run_intersect`（缓冲结果与 area-b）。用户写下的名字覆盖选中图层；选中图层只在用户没点名时填「当前图层」，分析且没点名时也可以填。
- 系统提示只加一句：能确定的操作直接执行，不要推测，也不要在做完后再分析一遍。

## 接口契约变更

- `POST /api/chat` 接受 `stream: true` 或 `Accept: text/event-stream`。事件为 SSE：`thought`（`reasoning` 或 `status`）、`tool`（线上工具名）、`final`，结束时另有 `done`（与原来的 JSON 字段相同，另带 `messages`）。不流式时仍返回 JSON，并带上 `messages`。
- 用户消息在模型返回前写入当前对话。失败时这条用户消息还在。
- 助手消息可带 `thought` 和 `thoughtKind`（`reasoning` 或 `status`）。
- 设置里的 `locale` 取 `zh-CN` 或 `en`，默认 `zh-CN`，随现有布局字段保存。
- `normalizeInstruction` / `explicitLayerTokens`。`resolveChatPlan` 在计划完整时返回 `execute`，不再把已填满的计划交回模型。
