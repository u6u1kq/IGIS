# 2026-10-11 V0.82 执行上下文隔离

V0.81 基线（commit 3102c7f）之上的修复版本。基线把 V0.76–V0.81 的累积变更按策略 A 整体入库，本版本在其上做两件事：修复执行上下文的并发串扰；把基线遗留的 typecheck 错误清零。

## 问题

`SpatialService` 把 `callerCrs` 与 `requestSource` 存在共享实例字段上，`usingCallerCrs`/`usingRequestSource` 用「保存→改→恢复」模式。desktop-api 全进程共享一个 service 实例，两个并发请求在 await 点交错时：

- A(desktop-ui) 的审计会被记成 B(cloud-ai) 的来源（归属串扰，活跃缺陷）；
- A 结束把字段恢复成 A 进来时的值，B 结束再恢复成 A 的值（脏残留）；
- `rejectCallerOverride` 读到别的操作声明的 callerCrs，会把不该拒绝的缓冲拒掉（潜伏缺陷：当时生产路径无人传 callerCrs）。

## 模块名

`packages/spatial-ops/src/service.ts`；`packages/provenance/src/ambient.d.ts`；`apps/cli/src/desktop-api.ts`；`apps/cli/src/v078-operation-check.ts`、`v078-correction-check.ts`、`v079-boundary-check.ts`、`v079b-boundary-check.ts`；新增 `apps/cli/src/v082-context-check.ts`。

## 变更内容

- **上下文 ALS 化**：两个实例字段换成模块级 `AsyncLocalStorage<SpatialCallContext>`（与同包 sink.ts 的 spatialResultSink 同模式）。`usingCallerCrs`/`usingRequestSource` 签名不变，内部 `callContext.run`；嵌套时内层从外层 store 继承另一字段，语义与原来的双字段独立保存一致。`rejectCallerOverride` 与 `remember()` 改读 ALS。不包 usingXxx 直接调用服务时上下文为空，行为与修复前一致（审计不带 requestSource）。调用方（executeGisOperation、map-http、workflow-env）零改动。
- **基线 typecheck 修复**（项目约定不装 @types/node，扩展手写 ambient.d.ts）：`node:crypto.randomUUID`、`node:path.sep`、`IncomingMessage.headers/resume`、`writeFile(Uint8Array, {flag:"wx"})` 重载、Buffer 全局（isBuffer/from/concat/indexOf/subarray/toString，兼容 Uint8Array 重载与 latin1）。desktop-api 上传响应的 `layers` 数组类型改为 `ReturnType<typeof publicStoreLayer>[]`（修复缺 message 字段的真实类型错误）。四个检查脚本的假请求补 `headers: {}` 与 `resume() {}`。
