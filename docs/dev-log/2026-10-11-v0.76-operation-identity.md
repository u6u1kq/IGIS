# 2026-10-11 V0.76 操作身份与回退顺序（补记）

本文为 2026-10-11 补记。V0.76 的实际开发早于本日志，内容依据当时的 TASK 文档与当前代码核对。

在 V0.75 的本地解析之上给操作建立身份，并把回退顺序改正确。没有 git 提交。

## 模块名

`packages/spatial-ops/src/operation-attempt.ts`，`buffer-operation.ts`，`buffer-operation-validate.ts`，`layer-resolution.ts`，`resolve-layer.ts`，`errors.ts`；`packages/llm-dispatch/src/registry.ts`；`apps/cli/src/conversations.ts`，`turn-rollback.ts`，`desktop-api.ts`。

## 变更内容

- Chat/MCP 的缓冲产生 `operationId`（`createOperationId`，格式 `op-<hex>-<hex>`），成功与失败都写 `var/operations` 的 OperationAttempt。当时只覆盖 buffer；intersect/clip/query/stats 没有进入这套记录。
- `validateBufferOperation` 只做结构校验：sourceLayer 必须是已解析身份，distance 必须是正有限数，unit 是 meters/kilometers/miles/feet/degrees，outputName 写了就不能是空串。不查图层，不查 CRS。
- `resolveLayerRef` 按 id → 精确名 → 忽略大小写 → 包含匹配，同名歧义返回候选不挑层；缓冲入口用专属文案解释歧义。Map HTTP 只认 layerId，GDL 仍用 `findByName` 同名取最上层。
- 回退改为先 `prepareTurnRollback` 写计划，再按图层、知识库、审计逐项删，全部完成才 `commitTurnRollback` 截短对话；单项失败不吞掉，保留剩余 id 供重试。仍是聊天轮级，Map、MCP、GDL 不进入。
- 失败路径保留审计事实：`auditRecordId` 已写入时随错误透出；审计追加本身失败置 `auditAppendFailed = true`，不伪造 id。
