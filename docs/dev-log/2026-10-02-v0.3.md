# 2026-10-02 V0.3 只读 GDAL-WASM、工具循环、账本与许可证

本轮把社区预编译包 `gdal-js@2.2.0` 接到只读路径，补上 LLM 工具调用循环、来源账本落盘，以及许可证锁的读写。没有 SurtGIS 算法，没有 ArcPy 业务，没有 DuckDB，没有嵌入库，没有 qgis-wasm，没有训练。未创建 git 提交。

`gdal3.js` 的许可证是 LGPL-2.1-or-later，直接链接被拒绝，没有安装。改用 MIT 的 `gdal-js@2.2.0`。其中的 GDAL 2.4 是 MIT/X，wasm 字符串写明 GEOS support not enabled。

`npx --yes -p typescript tsc -p tsconfig.json --noEmit` 退出码为 0。

## gis-io

- 模块名：`@igis/gis-io`
- 变更内容：每次到达路由器的读取都写入来源账本。成功结果增加非坐标元数据。GDAL 失败若带 `forwardToBackend: true`，仍把同一次请求转给 ArcPy 注入槽。路由本身不导入 gdal。
- 接口契约变更：`routeGisRead` 增加必填的 `ledger`。`GisReadResult` 增加 `metadata`。`GisIoReadError` 增加 `code` 与 `forwardToBackend`。`GisIoRoutingError` 增加 `forwardToBackend`。新增 `GisFieldMetadata`、`GisLayerMetadata`、`readSourceDigestMaterial`。
- 未解决问题：打不开源字节时，账本改为对路径字符串做 SHA-256，记录里仍然只有摘要。要素数量在适配器里有上限，超过上限会失败而不是返回截断结果。

## gdal-wasm-adapter

- 模块名：`@igis/gdal-wasm-adapter`
- 变更内容：用 `gdal-js@2.2.0` 做只读打开。支持把 GeoTIFF、shapefile 和 `.gdb` 目录复制进 wasm 内存文件系统后以 `GDAL_OF_READONLY` 打开。不调用 Create、CreateCopy、写回，也不派生外部 GDAL 进程。OpenFileGDB 读取器在驱动缺失或打开失败时返回可转发错误。
- 接口契约变更：`GDAL_WASM_IMPLEMENTATION` 从 `deferred-v0.3-1` 改为 `gdal-js@2.2.0`。`GDAL_BUILD.status` 改为 `pinned`。新增 `createGdalWasmReadPort`、`probeGdalDrivers`、`createOpenFileGdbReader`、`runGdalWasmSelfCheck`。`GdalReadOnlyAdapter.toMemory` 仍只有接口，没有把数据转成 GeoArrow。
- 未解决问题：自检打开了合成 GeoTIFF 和合成点 shapefile。OpenFileGDB 驱动在构建里（`GDALGetDriverByName` 非空），但没有合法 `.gdb` 夹具，无效目录会失败并 `forwardToBackend: true`，不能把它说成已经读通 ArcGIS FileGDB。FileGDB SDK 驱动不在这个包里。shapefile 的坐标系来自旁边的 `.prj`，因为该预编译包没有导出空间参考的 WKT 写出函数。`toMemory` 仍未实现。

## io-openfilegdb

- 模块名：`@igis/io-openfilegdb`
- 变更内容：注释指向适配器里的只读实现，并再次写明不等价于 ArcGIS Pro。
- 接口契约变更：无。`OpenFileGdbReader` 与 `OpenFileGdbSession` 的方法没有改。
- 未解决问题：本包仍然没有自己的打开代码。真实 gdb 的成功读取还没有夹具。

## llm-dispatch

- 模块名：`@igis/llm-dispatch`
- 变更内容：增加工具注册表、分发前参数校验，以及把工具结果送回模型的循环。执行通过注入的适配器，本层不做缓冲或相交。网络错误和超时会返回，超时可配置，到点不再等待。自检全部使用注入的 fetch。
- 接口契约变更：新增 `GIS_TOOL_REGISTRY`、`validateToolArguments`、`runLlmToolCallLoop`、`ToolAdapterPort`、`runLlmToolLoopSelfCheck`。`LlmCallerOptions` 增加可选 `timeoutMs`，默认 30000。`LlmInvokeError` 增加 `unknown-tool`、`invalid-tool-arguments`、`network-error`、`timeout`、`adapter-error`、`max-rounds`。原有的 `invokeLlmForToolRequest` 仍可用。
- 未解决问题：默认注册表只有 `io.read` 和 `io.listLayers`。模型若只返回普通文本、不返回工具调用，循环把它当作结束，不再猜测工具名。没有探测线上提供方。

## provenance

- 模块名：`@igis/provenance`
- 变更内容：账本可以写入 `var/provenance` 再读回。读盘时同样拒绝禁止键，包括嵌套对象。内存 API 保留。gis-io 的每次读取都会追加一条记录：源内容 SHA-256、`readOnly: true`、`exportPath: null`、已知图层名。
- 接口契约变更：新增 `readProvenanceDirectory`、`InMemoryProvenanceLedger.load`、`runProvenancePersistenceSelfCheck`。`ProvenanceRecord` 字段没有增加坐标或范围。
- 未解决问题：`recordId` 仍不在 `audit.json` 的 `recorded` 列表里。十六进制 WKB 若塞进非禁止键的字符串，键扫描发现不了。

## license-check

- 模块名：`@igis/license-check`
- 变更内容：可以读写 `config/licenses.lock.json`。新依赖先评估，不通过就不写入 `dependencies`。`gdal-js`（MIT）和其中的 GDAL（MIT/X）已写入。`gdal3.js`（LGPL-2.1-or-later）只出现在 `rejectedCandidates`，没有安装。
- 接口契约变更：新增 `readLicenseLock`、`writeLicenseLock`、`recordReviewedDependency`、`recordRejectedCandidate`、`LicenseCheckError`、`runLicenseLockIoSelfCheck`。`evaluateDependency` 的判定规则没有改。
- 未解决问题：仍然不解析完整的 SPDX `OR` / `AND` 表达式，也不挂钩 npm install 的生命周期。

## cli

- 模块名：`@igis/cli`
- 变更内容：新增无界面的读取演示 `apps/cli/src/read-demo.ts`。它接受文件路径，打印元数据 JSON，并把账本写到 `var/provenance`。ArcPy 只是会失败的注入槽。
- 接口契约变更：`COMMAND_GROUPS` 里 `io` 的摘要文本更新。演示文件不是库 API。
- 未解决问题：没有交互式命令行，也没有安装 tsx。运行方式见 README。

## shared-types

- 变更内容：注释改为 V0.3 已接上只读元数据，DuckDB 与 GeoArrow 仍未做。
- 接口契约变更：无。
- 未解决问题：控制面里的范围四元组仍然只留在进程内。

## config 与文档

- 模块名：`config`、`README.md`、架构说明、第三方声明
- 变更内容：`gdal.lock.json` 钉死 `gdal-js@2.2.0`，并写明 OpenFileGDB 的驱动缺口与夹具缺口。`licenses.lock.json` 记下通过项和被拒绝的 `gdal3.js`。README 写了演示命令。
