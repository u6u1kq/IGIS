# 开发规范

以下规则适用于本仓库的修改。不确定时标记 UNKNOWN，不要把代码存在写成功能完成。

Phase 0.11 的 15 条写在第一节。审计稿里已有的 15 条原文保留在第二节，没有删除。两边含义相同的都继续有效。第二节里多出来的义务（跑相关测试、说明 Undo/History、不得把代码存在说成功能完成）也继续有效。

## Phase 0.11

1. 一个任务解决一个主要问题。
2. 修改前先说明范围。
3. 不得擅自扩大任务。
4. 不得因修 Bug 顺手重构整个模块。
5. 不得删除未确认的旧功能。
6. 不得新增第二套相同功能。
7. 新 API 必须说明输入输出。
8. 新 Tool 必须定义输入 Schema。
9. 修改 GIS 状态必须说明副作用。
10. 修改 Geometry 必须说明数据去向。
11. 涉及 LLM 必须说明信任边界。
12. 未运行的测试不得声称通过。
13. 未验证的功能必须标记「未验证」。
14. 不确定问题必须写入 UNKNOWN。
15. 发现架构问题时先报告，不自动扩大修改范围。

## 审计稿原文（仍有效）

1. 不得未经任务授权扩大修改范围。
2. 修改前先说明目标文件和影响范围。
3. 不得删除现有功能作为简化方案，除非明确授权。
4. 新功能必须接入现有架构，不得私自建立第二套实现。
5. 新增 API 必须说明输入输出。
6. 新增 Tool 必须说明 Schema。
7. 涉及数据修改必须说明 Undo/History 行为。
8. 涉及 LLM 必须说明信任边界。
9. 涉及 Geometry 必须说明数据流向。
10. 发现架构问题时先报告，不要顺手大规模重构。
11. 一个任务尽可能对应一个明确目的。
12. 修改后必须执行相关测试。
13. 不得声称未运行的测试通过。
14. 不得把代码存在描述成功能完成。
15. 不确定的问题必须标记 UNKNOWN。
