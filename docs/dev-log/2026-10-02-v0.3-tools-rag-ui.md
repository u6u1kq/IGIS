# 2026-10-02 V0.3 工具、本地检索与试用界面

本轮在现有 LLM 客户端和 gis-io 读取上增加三个只读工具、本地 sqlite-vec 检索，以及三栏试用界面。没有重写 LLM HTTP 客户端，没有改 gis-io 的回退路由、TCP、模式枚举或端口。没有微调，没有地图，没有空间分析。未创建 git 提交。

## 工具注册

- 模块名：`@igis/llm-dispatch`、`@igis/gis-tools`、`@igis/gdal-wasm-adapter`
- 变更内容：现有 `GIS_TOOL_REGISTRY` 增加 `list-layers`、`get-layer-metadata`、`get-sample-feature`，JSON Schema 仍由 `toOpenAiTools` 生成。执行走注入的适配器，适配器调用现有 `routeGisRead`。样例最多 15 条，只读属性、序号和几何类型；预编译包没有导出 `OGR_F_GetFID`，序号不是 OGR FID。失败继续抛 `GisIoReadError`、`GisIoRequestError`、`GisIoRoutingError`。工具调用另写一条账本：工具名、源 SHA-256、图层名、成败、耗时。
- 接口契约变更：`ToolName` 增加这三个名字。`ToolAdapterPort.execute` 改为返回未知 JSON，循环仍用现有几何检查拒绝坐标字段。新增 `gisQueryTools`、`createScriptedGisMock`、`createLocalChatMock`、`runAssistantTurn`。`ProvenanceRecord` 增加可选的 `toolName`、`success`、`durationMs`。
- 未解决问题：`gdal-js@2.2.0` 不能读出要素 FID。样例读取为了不超过 15 条，不走会数完全部要素的元数据扫描；图层列表和元数据仍调用现有读取，那条路径会为了要素数量遍历图层。工具循环里非 `LlmInvokeError` 仍会被原客户端包成 `adapter-error`，消息保留 gis-io 原文。

## 本地检索

- 模块名：`@igis/rag-meta`
- 变更内容：选用 npm 包 `sqlite-wasm-vec@0.1.11`，许可证 Apache-2.0。其 `sqlite3.wasm` 静态编入 sqlite-vec `v0.1.7-alpha.2`（上游双许可 MIT 或 Apache-2.0，本仓库按 MIT 使用）。官方 `sqlite-vec` npm 包只提供原生动态库，不是 WASM。`sqlite-vec-wasm-demo` 只为浏览器编译，在 Node 里会拒绝启动，因此没有保留。加载位置是 `packages/rag-meta/src/store.ts` 的 `loadSqliteVecWasm`：读入 `node_modules/sqlite-wasm-vec/sqlite-wasm/jswasm/sqlite3.wasm`，初始化后查询 `vec_version()`。`SqliteVecRagStore.init` 每次打开都执行 `CREATE TABLE IF NOT EXISTS rag_entries` 和 `CREATE VIRTUAL TABLE IF NOT EXISTS rag_vectors USING vec0(embedding float[64])`。嵌入是本地三元组哈希，不调用云端。库文件在 `var/rag/kb.sqlite`。增加、删除、清空、检索都写账本，不写正文坐标。
- 接口契约变更：新增 `loadSqliteVecWasm`、`openSqliteVecRagStore`、`SqliteVecRagStore`、`embedText`。`RAG_IMPLEMENTATION` 改为 `sqlite-wasm-vec`。原来的 `RagStore` 抽象仍在。
- 未解决问题：官方 WASM 不能对 SQLite 动态 `load_extension`，所以扩展是随 wasm 一起加载，而不是单独再挂一个 `.wasm` 侧模块。Node 构建没有宿主文件系统，数据库用 `sqlite3_js_db_export` 落到 `var/rag`。`vec0` 的 k 近邻必须带 `k = ?`。Node 的 `readFile` 返回 `Buffer`，不能直接交给 `allocFromTypedArray`，恢复时先复制成普通 `Uint8Array`。启动时仍会打印一条 OPFS 线程警告，不影响读写。

## 试用界面

- 模块名：`apps/cli` 的 `desktop-api.ts`，`apps/desktop`
- 变更内容：本机 `127.0.0.1:39221` 提供三个面板：导入文件、模型设置、对话。预处理和检索、模型调用都在 TypeScript。设置写入已被忽略的 `config/llm.local.json`，对话写入 `var/desktop/messages.json`。Tauri 2 工程在 `apps/desktop/src-tauri`，窗口只打开上述地址，Rust 里没有 GIS、检索或模型实现。
- 接口契约变更：新增 HTTP：`GET /api/health`、`GET/PUT /api/settings`、`POST /api/import`、`GET /api/messages`、`POST /api/chat`。设置接口不回显密钥。
- 未解决问题：见文末工具链。没有安装 Tauri 的系统依赖时，窗口不会出现。页面本身由 `desktop-api` 提供。

## 命令行

- 模块名：`apps/cli/src/read-demo.ts`
- 变更内容：保留原来的路径和 `--fallback` 读取。新增 `tools` 与 `rag add|delete|search|clear`。
- 接口契约变更：无库 API。`tools` 和 `rag` 只在第一个参数匹配时进入。
- 未解决问题：文件名本身如果就叫 `tools` 或 `rag`，会被当成子命令。

## 许可证

- 模块名：`@igis/license-check`（逻辑未改）
- 变更内容：通过现有 `recordReviewedDependency` 写入 `sqlite-wasm-vec`。直接 GPL 没有加入。
- 接口契约变更：锁文件多一条允许的依赖。`policy` 规则没有改。
- 未解决问题：门禁仍不解析 SPDX `OR`。锁文件记录的是 npm 包 `sqlite-wasm-vec` 的 Apache-2.0。其内嵌的 sqlite-vec 上游是 MIT OR Apache-2.0，第三方声明按 MIT 使用，没有单独再加一条依赖。

- 模块名：类型检查与桌面窗口
- 变更内容：`npx --yes -p typescript tsc -p tsconfig.json --noEmit` 退出码 0。
- 接口契约变更：无。
- 未解决问题：本机没有 `rustc` 和 `cargo`，没有安装 Rust 工具链，Tauri 窗口没有启动。试用界面用 `npx --yes tsx --tsconfig tsconfig.json apps/cli/src/desktop-api.ts`，浏览器打开 `http://127.0.0.1:39221`。装好 Rust 后，在 `apps/desktop/src-tauri` 执行 `cargo tauri dev`。
