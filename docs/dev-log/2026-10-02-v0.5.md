# 2026-10-02 V0.5 地图与空间分析

在 V0.4 试用界面上追加地图画布、Turf 空间分析和平行审计。没有 git 提交。旧的 RAG、来源账本读写、shp 预处理、模型 HTTP 适配器、对话、底部工具栏、齿轮设置和 GIS 导入对话框都保留。gis-io 的 fallbackBackendMode 和 TCP 端口没有改。

## 地图画布

- 模块名：`apps/desktop/ui`（`index.html`、`app.css`、`app.js`），静态资源由 `apps/cli/src/desktop-api.ts` 追加的 `/vendor/maplibre/*` 从 `node_modules/maplibre-gl/dist` 读出。
- 变更内容：对话仍是主表面。右侧增加 MapLibre GL JS 画布、图层列表（显示、改名、透明度、填充色、轮廓色、轮廓宽度）、平移、滚轮缩放和框选。点击要素弹出属性表，弹窗里不写坐标进审计。视图的缩放和中心写在 `localStorage` 键 `igis.v05.mapView`，样式写在 `igis.v05.layerStyle`，不存整份几何。导入对话框增加「预处理成功后载入地图」，默认不勾选。
- 接口契约变更：新增 `GET /api/map/layers`、`GET /api/map/layers/:id/geojson`、`POST /api/map/load`、`POST /api/map/rename`。原来的 `POST /api/import` 请求体不变。GeoJSON 几何只走单独的读取路径；元数据接口没有删字段。
- 未解决问题：没有把投影坐标转成经纬度。shp 若不是经纬度，地图位置可能不正确。单层载入上限 8000 个要素。

## 空间分析

- 模块名：`packages/spatial-ops`。几何运算使用 `@turf/turf@7.2.0`（MIT）。shp 几何由 `packages/gdal-wasm-adapter` 新增的 `readVectorLayersAsGeoJson` 经 `OGR_G_ExportToJson` 导出，不改原来的元数据读取。
- 变更内容：缓冲、相交、裁剪、空间查询（属性筛选、点在面内、相交）、数值字段最小/最大/平均。损坏几何按要素跳过或整层返回中文错误，不让进程退出。结果写成新的 GeoJSON，路径与源文件不同；导出遇到已有文件会拒绝覆盖。
- 接口契约变更：新增 `POST /api/spatial/run`、`POST /api/map/export`。模型工具登记在原有 `GIS_TOOL_REGISTRY`，名字是 `map.buffer`、`map.intersect`、`map.clip`、`map.query`、`map.stats`。参数只有图层标识、距离、单位、查询种类、属性筛选文字和字段名。`POST /api/chat` 仍返回 `reply`、`calls`、`retrieved`，并额外带上 `layers`（图层标识和 geojson 地址，不含几何正文）。自检里的未知工具名 `vector.buffer` 仍然未知。
- 未解决问题：相交和裁剪每层超过 600 个要素会拒绝，缓冲超过 2000 会拒绝。非面要素相交时保留相压盖的原要素，不切开几何。没有网络分析、拓扑修复、三维或 DuckDB。

## 审计与知识库

- 模块名：`packages/provenance` 的 `spatial-audit.ts`。记录放在 `var/spatial-audit`，与 `var/provenance` 里的旧来源记录分开。旧记录字段 `sourceContentHash`、`hashAlgorithm`、`readOnly`、`exportPath`、`layerNames`、`recordedAt` 的读写没有改。
- 变更内容：缓冲、相交、裁剪、空间查询、统计、载入地图和导出各追加一条平行记录。字段有操作类型、输入图层名、非坐标参数（距离、单位、属性筛选文字、查询种类）、输出文件路径、时间、模型名、操作者 `local`，以及图层标识和成败说明。像坐标的筛选文字会省略。可选把图层名、操作类型、要素数量和字段名写入现有 sqlite-wasm-vec，不写坐标。
- 接口契约变更：新增 `GET /api/audit`。页面审计抽屉可列出这些记录，并按图层标识或输出路径把历史结果载入地图。
- 未解决问题：没有登录系统，操作者固定为 `local`。审计说明里的统计数字来自非坐标字段；字段名像经纬度时只记要素数量。
