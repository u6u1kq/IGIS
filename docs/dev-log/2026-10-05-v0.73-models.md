# 2026-10-05 V0.73 模型预设名与地址

在 V0.73 上只改预设表和填入这些值的文案。没有 git 提交。没有改 `config/llm.local.json`，没有打印或改写已存密钥。没有重写 HTTP 客户端、工具循环或 RAG。

## 模型预设

- 模块名：`packages/llm-dispatch/src/session-config.ts`，`providers.ts`，`apps/desktop/ui/index.html`，`app.js`，`apps/cli/src/desktop-api.ts`，`report-ppt.ts`，`config/llm.api.example.json`。
- 变更内容：
  - 预设改成厂商文档里的 chat 模型 id（均声明支持 tool / function calling）：`deepseek-flash`、`qwen3.8-max`、`grok-4.7`。界面标签与请求体里的 `model` 相同。
  - OpenAI 兼容基址按文档填写：DeepSeek `https://api.deepseek.com`（请求拼成 `/chat/completions`），千问中国站 `https://dashscope.aliyuncs.com/compatible-mode/v1`，xAI `https://api.x.ai/v1`。
  - 点选预设仍只填入模型名和地址，用户可以改。local-mock 与自定义一行未删。
  - 旧选择名 `DeepSeek-V4.1-Flash` 仍被接受，映射到新的 `deepseek-flash`。已保存的错误 id 不会自动改写；下次点选预设才发出新 id。
- 接口契约变更：无新 HTTP 路径。`GET /api/llm/config` 的 `presets` 里 label / model / baseUrl 换成上表。
- 未解决问题：没有用磁盘上的密钥打真实 API。未勾选保存时，进程内存里的旧模型名会一直用到用户再选一次预设。千问专属域名需要 WorkspaceId，预设仍用文档中仍可用的共享中国站 compatible-mode 地址。
