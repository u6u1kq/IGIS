# 2026-10-04 V0.6 模型弹窗、知识库与图层列表

在 V0.5 上追加。没有 git 提交。地图画布、空间分析表单、单层样式、GeoJSON 导出、RAG 检索、`var/spatial-audit` 和对话账本都保留。对话账本仍然只存角色和文本，不存坐标。新界面不解析 shp、gdb、mif，也不在新路径上调用 GDAL。没有 Electron、Tauri 或 cargo。

## 模型选择

- 模块名：`apps/desktop/ui`，`apps/cli/src/desktop-api.ts`，`packages/llm-dispatch/src/session-config.ts`。
- 变更内容：对话输入下方的模型下拉改成按钮。点击后打开模型对话框。上面是 DeepSeek-V4.1-Flash 和 local-mock。高级设置默认折叠，里面是 API Base URL 和密码框。测试连接把当前表单交给 `POST /api/llm/test`，结果用中文显示。local-mock 在本机直接成功，不访问网络，并忽略地址和密钥。DeepSeek 预设是 `https://api.deepseek.com`、模型 `deepseek-v4.1-flash`、提供方 `deepseek`，高级设置里的地址可以覆盖预设。取消只关掉对话框，不提交。确认才提交。保存配置到后端默认不勾选。V0.4 齿轮对话框和这个弹窗都收集密钥，已去掉齿轮，避免两处同时改密钥。空间分析表单和单层样式控件没有改业务逻辑。
- 接口契约变更：新增 `GET /api/llm/config`、`POST /api/llm/config`、`POST /api/llm/test`。确认请求体是 `model`、`apiBase`、`apiKey`、`persist`。响应没有完整密钥；内存里的用户密钥只回掩码，仅来自环境变量时只报告已配置、不回任何密钥字符。有效配置是：用户已确认的内存覆盖优先，否则 `DEEPSEEK_API_KEY` 和预设地址。现有 HTTP 适配器没有改，前面加了 `resolveEffectiveLlmConfig`。`PUT /api/settings` 现在只更新检索开关和 topK，不再从这里写入密钥；只有已经勾选过保存时，检索开关才会跟着写回 `config/llm.local.json`。
- 密钥：默认只在 desktop-api 进程内存。页面刷新后密码框为空，不把密钥放进浏览器。未勾选并确认时不写 `llm.local.json`，若该文件已存在会删掉，这样进程重启后内存配置消失，改回环境变量。勾选后写入 gitignore 的 `config/llm.local.json`，并带 `"persist": true`。启动时只读取带这个标记的文件。没有该标记的旧文件不会自动载入。错误响应会先去掉密钥和 Bearer 片段，服务端不打印密钥。
- 未解决问题：自定义接口若使用别的模型名，测试仍按 `deepseek-v4.1-flash` 发一次最小对话。环境变量里的密钥不会出现在掩码里，页面只知道“有密钥”。

## 知识库

- 模块名：`packages/rag-meta` 的列表方法，`apps/desktop/ui` 的知识库对话框，`apps/cli/src/desktop-api.ts`。
- 变更内容：知识库页列出已存文档，每行可以单独删除。清空全部仍在。添加文本时，超过 1MB、无法按 UTF-8 解析、或文件名是 shp/gdb/mif 等矢量后缀，都返回中文说明，进程不退出。列表不含正文，也不把几何坐标写入向量库；正文若像几何文本，沿用原来的拒绝写入。
- 接口契约变更：新增 `GET /api/rag/documents`、`POST /api/rag/add`、`POST /api/rag/delete`、`POST /api/rag/clear`。单条删除调用原来的 `store.delete`。命令行里的 clear 没有去掉。
- 未解决问题：知识库上传是浏览器读成文本再提交，不是直接接收 shp。大文件在读满约 2MB 请求体后拒绝。

## 图层列表

- 模块名：`apps/desktop/ui`，`packages/spatial-ops/src/catalog.ts` 的 `remove`，`apps/cli/src/map-http.ts`。
- 变更内容：地图侧在原有单层样式上面加了图层列表。每一行是名称、显示勾选和只删该层的按钮。点一行就让原来的透明度、填充色、轮廓色、轮廓宽度（以及改名）指向这一层。删除只去掉该层在地图目录里的生成文件，不删源数据，不调用 GDAL。
- 接口契约变更：新增 `POST /api/map/layer/delete`，请求体是 `layerId`。`POST /api/spatial/run`、`POST /api/map/export` 和空间分析表单没有改。
- 未解决问题：删除图层不会写一条新的空间审计。审计文件格式没有改。

## 明确没改的部分

- `var/spatial-audit` 的记录格式和 `packages/provenance/src/spatial-audit.ts` 没有改。
- 对话账本 `var/desktop/messages.json` 仍只有角色、文本和时间，不存坐标。
- 空间分析表单的缓冲、相交、裁剪、查询、统计、写入知识库勾选和 GeoJSON 导出没有改业务代码。
- 没有新增 GDAL 依赖，新的模型、知识库和删图层路径不调用 GDAL。
