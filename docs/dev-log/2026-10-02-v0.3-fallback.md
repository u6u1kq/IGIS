## gis-io

- 模块名：`@igis/gis-io`
- 变更内容：删除 `forwardToBackend` / `forwardToArcPy`。固定先用 `gdal-js@2.2.0`（MIT）。成功立即返回。失败后读 `fallbackBackendMode`：`off`（默认）返回错误且不打开 TCP；`arcpy` 把同一次读取请求发到 `arcpyBackendPort`；`qgis` 发到 `qgisBackendPort`。两端都只是本机 `127.0.0.1` 的套接字收发、错误和超时，没有 GIS 业务。来源账本仍对每次读取计算 SHA-256，不记录几何坐标、范围、WKT/WKB。
- 接口契约变更：新增 `FallbackBackendMode`、`GisIoFallbackConfig`、`DEFAULT_GIS_IO_FALLBACK_CONFIG`（`off`，端口 `49221` / `49222`）、`loadGisIoFallbackConfig`、`GIS_IO_BACKEND_TIMEOUT_MS`。配置文件是 `config/gis-io.json`。`routeGisRead` 增加可选第四参，省略时为 `off`。`GisIoReadError` 与 `GisIoRoutingError` 不再带 `forwardToBackend`。`GisReadResult.reader` 增加 `qgis`。
- 未解决问题：仓库里没有 ArcPy 或 QGIS 进程，也没有 QGIS 异常适配。TCP 超时 8 秒，响应超过 1 MiB 会丢弃。OpenFileGDB 仍没有合法 gdb 夹具。
